### 已配置本机的启动方式

1. 用Open-WeChat.cmd打开配套微信并完成登录，已有配套微信登录可保持。
2. 运行Start-WeChat.cmd，自动清理本项目旧启动器、读取服务、桥接与AstrBot，再启动新实例；保留已登录微信。Start-WeChat-Live.cmd先把本机模式保存为live再启动；普通入口沿用当前配置。两者任选一个；重复打开会替换旧实例。其他程序占用端口时会保留该程序并报错。
3. 运行View-Context.cmd访问8768。首次更新需先关闭旧查看器再打开；只刷新HTML不会更新旧后台。选择微信群后可重载角色卡/提示词或清空当前工作上下文，长期记忆与原始记录保留。
4. Monitor-Context.cmd打开8767用量监视页。实际请求正文在8768查看，两者用途不同。

程序普通回复软引导为20—100字、允许更短；群卡2.4的日常表达偏向1—10字，本地不补字，整次兜底160字；超过15字由同一次生成以<|msg|>标记2—3个语义段，依次确认发送，失败结果不明时停止且不自动重发。无自然断点时保留一条。

主conversation已开启thinking，档位low、总输出上限8192、超时120秒；这不是额外独立的8192推理预算。可在config/engine.toml将reasoning_effort改回high。后台摘要/情绪/记忆审查未因此统一开启推理。单请求预算1M、650k压缩、群工作窗口200k、共享日预算50M保持不变。

以下为通用桥接说明与初始默认值；本机完成配置后的启用状态以私有配置为准。

这是独立于原 MYATRI 私聊库的 AstrBot 接入项目。AstrBot 负责平台收发，本地 MYATRI 0.2.8 负责小温暖的人格、上下文、记忆和维护。通用桥接之外，0.1.1 增加了 WeChatAgent 平台及其本机准备入口。

通用源码初始默认值：**offline 模式、空群白名单、插件关闭**。本机已登录并绑定测试群；当前模式由私有配置决定。0.1.2已按授权迁移私聊冻结快照；本次迁移和验证未调用模型或发送微信消息。

## 使用

1. 双击 `Start-Bridge.cmd`。启动 `http://127.0.0.1:8766` 后端（首次默认离线，已有配置沿用mode），并将插件放入独立 AstrBot 的插件目录。
2. 双击 `Start-AstrBot.cmd`，打开 AstrBot 管理面板，默认地址 `http://localhost:6185`。面板首次启动可能需要准备前端资源。
3. 选择并配置一个**实际支持微信群收发**的 AstrBot 平台适配器。它必须提供稳定的群ID、成员ID、消息ID；仅能识别昵称或只支持个人私聊的接口不够。
4. 在 `config/bridge.local.toml` 将 `allowed_groups` 改成实际的 `平台实例ID|群ID`，例如 `allowed_groups = ["wechat-test|123@chatroom"]`，重启后端。
5. 在 AstrBot 的“小温暖 MYATRI 桥接”插件设置中填相同白名单，确认 token 文件绝对路径，启用插件。**先保持后端 offline**，用测试群的@或 `/warm 内容` 验证收发。
6. 收发验证后，再把后端配置 `mode = "live"` 并重启。模型凭据从现有 Windows 凭据读取；没有复制或保存你的模型 Key。在 AstrBot 中不需要再填一份 DeepSeek Key。

专用于小温暖的 AstrBot 建议关闭内置 LLM 自动回复，即 `provider_settings.enable = false`。插件处理命中白名单的事件时也会停止后续流水线，避免双重调用。插件处理白名单群文字，支持@、关键词及10%随机接话；暂不处理私聊、图片和语音。

准备和离线检查：

```powershell
uv sync --frozen
.venv/Scripts/python.exe scripts/prepare.py
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m ruff check src astrbot_plugin_myatri scripts tests
```

## 记忆与身份

每个 `平台实例ID + 机器人ID + 群ID` 独立存档，同群成员共享群上下文。入站原话作为 JSON 信封中的 `text` 原样保留，并带成员ID、昵称、消息时间；昵称不是身份认证。当前群模板为角色卡2.4；实际加载版本由运行库决定。默认新群不会复制原私聊档案；本机当前群已获用户明确授权，在0.1.2迁入原 `var/xiaowennuan` 的冻结历史（含旧ATRI记忆），原库保留且后续新增消息不自动同步。

群内不会自动把所有成员认作菅蘧，或把其他人的发言当成你的偏好。跨群记忆不互通；这次授权范围仅为当前群，其他群若要迁移需另行明确选择来源和可见范围。

## 频率与送达状态

正文通常20—100字、160字本地兜底；诊断30轮、记忆与情绪50轮、深度整理150轮、人格审阅300轮；1M上下文配置、650k压缩阈值。所有桥接群共享一个50M日预算账本。原命令行私聊库的预算仍是另一个账本，并不构成账号总额限制。

后端生成回复后标记 `prepared`；插件先原子领取为 `sending`，发送接口返回后记 `sent`。异常或发送中进程退出记 `unknown`，不会自动重发。`sent`仅表示适配器发送调用成功返回，不代表成员已读；若适配器本身不提供真实回执，无法证明服务端最终投递。生成记录不等于送达事实。

## 项目组成

- `upstream/AstrBot/`：实际克隆的上游4.29.1，commit锁定在 `UPSTREAM_LOCK.json`。
- `vendor/`：已核对的 MYATRI 0.2.8 wheel，无私聊运行库及本机凭据；新项目无需依赖原项目的虚拟环境。
- `astrbot_plugin_myatri/`：独立插件源码。
- `src/myatri_bridge/`：本机HTTP后端、群隔离与投递状态。
- `locks/astrbot.uv.lock`：AstrBot依赖锁；准备脚本复原并检查一致性。
- `docs/MYATRI既有修改记录.md`：既有修改与本次更新入口。
- [Word版修改记录与接入说明](docs/MYATRI修改记录与AstrBot接入说明.docx)：3页摘要，已逐页检查排版。
- `docs/接入设计与验收.md`：改动范围、限制、验证与尚需确认的信息。

本机生成的 `var/bridge-token.txt` 仅用于桥接鉴权，不是模型Key。服务只监听127.0.0.1，不支持直接暴露公网；当前启动方式是同机部署。
