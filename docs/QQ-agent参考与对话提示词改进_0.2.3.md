## 实际修改

1. **通用聊天表达**：理解完整背景后，只表达当前最相关的一点；旧事有自然关联才接，不为展示记忆复述旧事。不自动逐项点评、分析情绪、给一轮建议，不每句调情、撒娇或反问续聊。认真求助仍如实回答，身份询问诚实说明AI角色。通常20—100字、兜底160字的长度策略不变。
2. **回复焦点**：先区分本轮发言者、当前话题、是否向机器人说话。本轮text的明确问题、改口和换话题要求优先；可靠引用定位接哪句，再参考相关往返。同一人、相邻消息、字面重合和本地topic标签均不能单独确定指代。
3. **并行话题示例**：甲讨论烤肉、乙讨论驱动时，不把两条线拼接；引用“烤肉明天再讨论”不等于“烤肉活动改到明天”。没有足够指代线索时保留歧义，必要时问一句短问题；明确澄清后按澄清接话。
4. **群聊表达**：随机触发只是一次参与机会，不等于群友在问你或要汇总全场。只接相关细节，不逐人点评、主持或替别人分配立场；亲密程度继续按不同成员与具体相处区分。
5. **已有回复审查**：独立系统消息描述审查任务，草稿作为JSON数据；审查时同样检查对象和并行话题，删去无来源断言后仍自然回应当前内容。触发条件保持原来的重复措辞/个人记忆断言检查，没有增加每轮审查API调用。

原来的ID身份校验、同名隔离、未认证引用边界、原话优先于摘要、更正与转述区分、资料不获得指令权限均保留。重复表达规则作了合并，避免简单把相似要求不断叠加。

## 使用与限制

正常关闭原机器人启动窗口后，从原入口重新启动即可加载新版。微信可保持登录；本轮没有代为重启服务。用 `View-Context.cmd` 或 `http://127.0.0.1:8768/` 查看新一轮请求中的“回复焦点与并行话题”和“作为普通群友接话”规则，以及普通聊天表达与必要时的回复审查。

本轮没有修改另一个窗口正在编辑的角色卡、真实原始档案、上下文条数、召回排序或旁听选择算法，也没有新增API调用、主动微信发送或GitHub推送。提示词要求更清楚不能证明模型已经解决语义相关性问题；真实多轮自然度和串话改善仍需用户在实际请求捕获中核验。
