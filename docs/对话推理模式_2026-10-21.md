# 对话推理模式（2026-10-21）

本次只在 MYATRI-AstrBot 桥接的 conversation 请求中开启 DeepSeek 思考模式。现有核心 wheel 不变，后台摘要、记忆提取、情绪和人格审查保持各自原来的设置。修改前目录已有多项其他改动，本次不重置或发布它们。

## 配置与启用

`config/engine.toml` 的 `[chat]` 新增：

```toml
thinking = true
reasoning_effort = "high"
thinking_max_tokens = 8192
thinking_timeout = 120
```

官方 Chat Completions 的实际档位为 low / high / max；high 是三档中间档，medium 也映射到 high。请求显式发送 `thinking: {type: enabled}` 和 `reasoning_effort: high`。

8192 是每次请求的推理与最终答案合计输出上限，不是每次必用量，也不是独立推理预算。原先正文输出上限不适合作为启用思考后的总上限；现有正文长度规则继续在最终正文上应用。请求超时改为120秒，上下文预算同步预留至少8192输出空间。输出仍可能耗尽；finish_reason=length 保持报错，不把未完成推理当成聊天回复。

需正常关闭旧机器人服务窗口，重新运行原来的 `Start-WeChat-Live.cmd` 才加载。微信可保持登录。本次未停止或启动现有服务，未进行远程API调用、微信发送或Git发布。

## 工具协议与记录

同轮工具请求继续回传供应商的 reasoning_content；未完成工具协议可从原有持久协议恢复。完成轮的最终 reasoning_content 单独保存在本群 runtime.sqlite3 的协议数据中，在后续 tools 请求选入该问答时完整回传。旧非思考历史没有推理内容，使用空字段；不为旧轮伪造推理。该字段不写成人格、用户事实或可检索记忆，现有上下文查看器和监视页不展示推理正文。监视页可查看实际请求开关、档位及API提供的推理Token计数。

## Token增量解释

输出量 = reasoning_tokens + 最终正文/工具输出tokens；reasoning_tokens 是 completion_tokens 的组成部分，不能再重复加到账本。每个工具往返都会额外请求；返回的历史推理还可能成为后续 tools 请求的输入。缓存命中影响费用，不意味着Token数量消失。

本机只读抽取最近100次成功 conversation 请求，用量中位数为输入18708、输出31 tokens。该样本混合了历史上下文配置和可能的工具子请求，不是固定同题对照。以下仅为无工具、输入近似不变时的算术情景，不是模型实测预测：若新增500 / 2000 / 5000推理tokens，则相对18739总tokens约增加2.7% / 10.7% / 26.7%。多轮回传会另增输入，最终正文长度也可能变化。实际增量需读取新usage，不能保证固定倍率。
