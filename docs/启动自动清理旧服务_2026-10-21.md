# 启动时自动清理旧服务（2026-10-21）

用户明确要求“打开这个CMD时自动清除旧服务”。两个入口 `Start-WeChat.cmd` 与 `Start-WeChat-Live.cmd` 继续共用 `scripts/start_wechat.ps1`，无需新的启动方式。

## 行为

在uv环境同步、插件复制和新服务启动之前，先识别并停止本项目之前的启动器、AstrBot、桥接及读取进程。原启动器仍占互斥锁时，先停止旧启动器及其子进程，再等待取得锁。手工启动、没有旧启动器的已知服务也会识别清理；清理后最多等待8秒释放5031、6185、8766。

进程归属由绝对程序路径、实际Python入口参数及虚拟环境父进程共同确认，兼容Windows venv转发到Conda解释器的情况。只选择创建时间早于当前启动器的进程，排除当前启动器及祖先进程；停止前再次核对创建时间、路径和命令行，防止PID复用。工具辅助代码在 `scripts/wechat_services.ps1`。

清理使用已确认PID的进程树终止。微信及30001端口、本机监视器8767/8768、其他项目的Python和不明端口占用者不在清理范围。未确认的端口占用会报错，不能仅凭端口号结束进程。不删除数据库、记忆、journal或配置文件。

这会中断旧实例正在处理的回复；发送结果不确定的任务继续沿用原有unknown不自动重发规则。新启动完成后再继续聊天。旧CMD可能留下退出后的提示，但它不再持有服务。

## 验证

在真正Windows PowerShell 5.1执行6项离线测试，模拟进程快照和终止接口，覆盖：有空格的项目路径、venv/Conda父子归属、旧启动器优先、保留微信/监视器/其他项目、拒绝入口参数伪匹配、新进程和祖先保护、PID复用检查、未知端口拒绝及已知进程清理成功。两个PS1通过同一解释器的语法解析。

测试会拦截真实终止函数，没有对当前用户服务执行清理或重启，没有微信发送或模型调用。本轮不上传GitHub。下次双击任一原启动CMD时自动生效。
