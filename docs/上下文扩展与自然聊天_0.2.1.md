# 上下文扩展与自然聊天 0.2.1

2026-10-21，用户已批准十项上下文/表达优化。本轮只做本地实现、离线测试与依赖更新，不代替用户重启服务、不调用付费模型、不发送微信、不自动上传 GitHub。

## 当前策略

| 部分 | 新设置 | 作用 |
|---|---|---|
| 群完整往返 | 默认80轮，可配置1—200轮 | 最近40轮优先，再按当前成员、话题、明确引用补足相关往返；以原时间顺序呈现，仅重放已确认发送的回复 |
| 群旁听窗口 | 默认100条，可配置1—200条 | 与完整往返按消息ID去重；当前消息不重复附带，明确引用的热库原文优先保留 |
| 普通召回 | 50000字符材料预算、每条最多4000字符片段 | 短记录可完整展示，长记录按查询选连续原文片段；显示实际起止位置与省略量，不能声称片段就是全文 |
| 会话摘要展示 | 60000 UTF-8字节 | 减少已有摘要仅展示很少条目的问题，保留来源和不确定性 |
| 群摘要展示 | 30000字符 | 保留关键逐字引文，按当前成员/话题选择；摘要仍不是原话或身份认证 |
| 授权继承历史展示 | 最多96000 UTF-8字节 | 仅扩大已有授权材料的展示，不扩大群之间或成员之间的记忆权限 |
| 私聊压缩后原话 | 最近最多80个完整往返，240000 UTF-8字节 | 整对选择，不把助手答复截成孤立一半；超额原文仍可按来源恢复 |
| 私聊语义整理 | 每批最多24项、每项最多600字符，输出最多8000 Token | v2提示保留互动过程、共同玩笑、未完话题和明确表达的当时感受，继续逐字校验来源 |
| 群工作窗口 | 200000保守估算额度 | 各部分共用可借用的空间，不凑Token；预算紧张时先减少旧旁听、相关度低的旧往返、摘要和背景，再减少近期整对往返 |
| 聊天表达 | 通常20—100字，程序兜底160字 | 简短回应可更短，不补字、不另调API改写；接续此前互动，不要求每次只看眼前一句 |

单请求配置上限仍为1000000，自动语义压缩阈值仍为650000，日额度仍为50000000；维护50轮、诊断30轮、旁听200条热库/100条一摘要/10份摘要及30天本机冷存档不变。

200000是本地估算的工作窗口上限，不是每轮必须占满的真实模型Token数。分项按UTF-8字节上界估计，不能与API实际Token数等同。原话较少时仍可能只有几万Token；不会填充无关历史来制造用量。群工作窗口通常会在650k之前进行本地选材；这不触发额外语义压缩API。固定角色、当前消息和明确引用原文过大时仍可能超过软目标，硬预算校验继续生效。

## 语义和身份边界

群摘要v2增加可选interaction_kind，记录话题、玩笑、未完回应、交往边界和明确表达的情绪。玩笑、未完话题、情绪线索必须是conversation或uncertain，不能提升为个人永久事实；转述、自述、否定、更正、未知归属、逐字引文校验均保留。摘要生成/支持审查仍按原有后台批次执行，没有新增每轮总结调用。

角色卡由另一个窗口编辑，本轮没有修改任何角色卡或将示例替换成固定台词；通用表达策略与渠道规则按本次批准放宽。原始档案不删不改，旧摘要保持原版本，不为更新提示词自动重新付费总结已有窗口。

## 如何使用与观察

正常关闭当前启动窗口，再用原入口重新启动。已运行的进程不自动换入新模块。双击`Monitor-Context.cmd`打开本机监视页，正常完成一轮聊天后可看到本轮完整往返数、旁听条数、摘要条目、分项字符/估算用量，以及窗口选择、预算和去重造成的省略计数。

每轮只附加无正文的统计；完整协议仍按30轮保存。断点重试使用本轮冻结统计，不混入下一轮的数据。监视接口只返回数值白名单，不返回原话、成员ID、来源ID、密钥或推理正文。API实际用量与本地构成估算分开显示；生成中仍不虚构逐Token进度。

## 安装与验证边界

核心与桥接均更新为0.2.1；桥接使用`vendor/myatri-0.2.1-py3-none-any.whl`，对应`UPSTREAM_LOCK.json`和`uv.lock`同时更新，避免只改核心源码而群聊仍运行旧依赖。上一轮微信接口缺失的启动诊断修复一并保留。

离线回归覆盖80轮完整往返、群消息冲刷后的旧互动、明确旧引用、未确认发送隔离、预算整对收缩、来源片段覆盖、丰富摘要、监视隐私和断点统计。测试能确认材料正确进入请求，不能替代真实模型对自然度、延迟和长期关系连续性的人工验收。此前真实模型长原文阅读仍待复测，本轮没有以离线通过掩盖该限制。
