# 实际上下文查看器 0.2.2

2026-10-21。用户要求直接查看上下文，以检查话题误接、原话与无关背景混在一起的问题。本轮增加本机查看与请求捕获，不调整相关性排序，不调用付费模型，不代替用户重启机器人。

## 打开与使用

双击项目根目录 `View-Context.cmd`，访问 `http://127.0.0.1:8768/`。查看器已在本机独立启动，不依赖微信服务重启；重复双击会复用已有查看器。原Token监视页也增加了查看原文的链接。

选择微信群聊或私聊库，然后选择：

- **最新实际请求捕获**：机器人加载新版后，保存最近5次主对话/回复审查请求。请求包含原始顺序的system/user/assistant/tool消息、工具定义、时间、请求用途、模型与尝试序号；保留完整正文，隐藏私密推理字段及明显密钥。
- **历史检查点**：读取旧版每30轮保存的完整协议，去掉最终生成的回复，以还原最后一次主对话输入。页面醒目标明旧快照与时间，不声称它就是最新一轮。旧协议没有保存当时工具定义或额外审查请求，这些部分不补造。

目前本机可用的群聊完整历史快照发送时间为2026-10-21北京时间12:30:37；这只是当时的记录。之后没有完整保存的轮次不能准确倒推。**要捕获接下来的每次真实请求，需要正常关闭并重新启动原机器人入口，再聊天一轮。** 只打开查看器不会生成聊天或调用模型。

页面支持按角色/类别筛选、搜索原文、逐条查看群信封内近期消息、查看本地选材依据和复制完整JSON。筛选不改变模型输入；复制包含被筛选隐藏的消息。自动刷新默认关闭，避免阅读时跳动。

## 如何判断接错话题的来源

历史对话卡片可展示 `recent_complete_turn`、`same_member`、`same_local_topic_hint`、`literal_text_overlap`、`explicit_reply` 等本地选材依据及分数。当前旁听窗口按近期消息进入，可能含同时进行的其他话题；同一成员、字面重合或本地话题提示都不保证语义相关。这些元数据只供调试，不是模型内部思考，也不额外塞回模型请求。

先核对当前发言者/当前原话，再查看附近群消息、旧往返与摘要分别带入了什么；原话完整在上方，解析后的资料仅作为辅助视图。不要将“材料在请求里”直接等同于模型正确理解了它。

## 捕获准确性与本机保存

捕获发生在预算预留成功后、调用模型供应商前，状态为 `prepared_for_provider`。这不证明服务器已经收到；查看器按trace_id关联原用量日志，显示received/failed等回执。工具往返和额外回复审查是独立请求，可从最近5个请求里分别选择。DeepSeek结构化请求实际追加的JSON Schema系统消息也会捕获。

每个运行库的 `context-debug/` 最多5个请求JSON，重试覆盖同trace_id的文件，使用原子替换；没有追加每轮总结API。捕获写入失败只记录固定提示，不阻断聊天。请求目录位于原有Git忽略的本机var运行库，不上传GitHub。普通统计接口仍不返回正文，全文只在独立查看器中展示。

公共配置默认不启用捕获；本次按用户要求已在本机私聊`config/live.local.toml`和群聊`config/bridge.local.toml`开启。分别关闭`[context].capture_requests`或`[bridge].capture_requests`并重启即可停止后续捕获；已保存的5份副本不会被冒充删除。角色卡与原始档案没有修改。

查看服务仅绑定127.0.0.1，使用浏览器本机会话Cookie，并拒绝跨站、伪造Host及写入请求；无外网脚本/CDN，原文通过textContent展示。它用于本机调试，不是对外共享接口。核心与桥接更新为0.2.2，冻结wheel和依赖锁同步。

## 验证

离线验证包含请求原顺序/字面文本、真实HTTPX模拟POST的schema系统消息一致性、失败/重试不增加调用、5份并发轮转、密钥与推理字段排除、捕获失败不影响聊天、本机HTTP访问边界、旧快照不冒充当前、回执精确关联、实际桥接捕获及UI筛选/复制/XSS文本安全。

本机只读核验已经可以显示群聊和两个私聊库的历史完整快照；尚未为展示捕获而调用真实模型。自然相关性问题仍需据新快照定位后处理。
