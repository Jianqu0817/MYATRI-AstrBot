# 微信语义分段发送（0.2.7）

角色卡不改。只在群聊运行提示词增加发送格式：总回复不超过15字时一条；超过15字优先按语义两条、必要时三条，以<|msg|>分隔。仍遵循原总长度和接话焦点，不为分段增加话题、开场或收尾；没有自然断点允许一条。

同一次生成完成分段，不增加拆句API。已有回复审查保留这个发送约定；最终正文去掉分隔符，完整回复作为一轮保存，reply_parts记录对应分段。程序最多发三条；未给分隔符时只在安全的完整句子边界兜底，保护引号内原话、代码和链接，不按字数硬切。

AstrBot插件按同群锁连续发送，前一条发送返回后才发下一条，使用既有WeChatAgent回执检查。每段确认写入sent_parts进度；重复回调、重复确认不会再发送或重复记录。中途错误/取消立即停止，保留已确认部分，整次标unknown，不自动重发；平台已发送但确认丢失时无法证明其结果，不能宣称严格恰好一次。

每段确认后的消息分别进入机器人已发上下文，并有各自发送时间和消息ID；完整批次确认后，历史只回放完整往返一次，旁听副本去重。分段不增加用户对话轮数或旁听的人类证据计数。旧客户端仍可一次发送reply并使用原确认接口。

120项定向离线检查通过（41.22秒），包括分隔符、15字边界、三段/总字数上限、引用/代码/链接、单次生成、逐段确认/顺序、部分失败与重启、重复回调、原发送链路及思考配置。Ruff通过。测试没有实际调用LLM或向微信发送消息，真实模型能否稳定按语义分段仍需试聊。

插件源码已同步到本机AstrBot插件目录；没有改变登录状态或已有渠道/模型配置，没有重启服务或上传GitHub。正常重启桥接和AstrBot后生效，微信可保持登录。仅微信/群桥分段，原命令行仍显示完整回复。
