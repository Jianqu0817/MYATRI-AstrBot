# Harness 升级与菅蘧专用电脑操作（2026-10-22）

## 已安装与范围

在 MYATRI-AstrBot 的 `var/harness/runtime` 独立安装并固定 `@deepseek-ai/dsh 0.2.1-rc.2`，从原来的 `0.1.2-alpha.1` 升级本项目电脑执行环境。旧 `~/.dsh` 的程序、profile、凭据及搜索回退保持原状。项目自带 Node 副本位于 `var/harness/node/node.exe`，版本 v24.21.0，不依赖旧安装日后是否被移除。

公开安装输入为 `config/harness/package.json`、`pnpm-lock.yaml` 和 `pnpm-workspace.yaml`，锁定依赖。pnpm 初次安装因未决定第三方构建脚本策略退出；检查脚本后，仅允许官方 subprocess 辅助程序的安装脚本，未启用本阶段不用的 node-pty/koffi 等构建。随后锁定安装返回0、CLI版本和真实工具运行时探针通过。原有 Python 依赖、vendor 0.2.8 wheel、核心 MYATRI 仓库与角色卡不修改。

`Harness.cmd` 默认显示新版版本；`Harness.cmd --help` 查看 CLI。手动 `Harness.cmd web` 使用独立 `var/harness/home`，不接管旧 Harness 进程。新的通用 UI 与本次桥接授权策略不是同一入口：桥接只通过下述三项能力执行，未把通用 UI、shell 或浏览器工具暴露给群聊。

本阶段的“电脑控制”明确限定为三个动作。没有安装/激活截图、鼠标键盘、浏览器或通用 PowerShell 代理，未宣称已实现任意桌面操作。

## 使用

由已绑定的菅蘧账号，在原有允许的群内发送：

| 命令 | 行为 |
|---|---|
| `/pc 打开记事本` | 启动固定的 Windows 记事本程序，不接受其他程序名、参数或路径 |
| `/pc 写便签 明天记得带书` | 将原样文本追加到 `var/computer-control/notes/便签.txt`，每次最多1000字 |
| `/pc 读便签` | 读取便签末尾最多1000个Unicode字符，明确返回是否截断 |

`/pc` 或不支持的动作只返回用法，不能改为任意命令。便签文本不作为代码、路径、提示词执行。写入采用追加并fsync，不覆盖原有便签。便签总大小有上限，拒绝符号链接、目录junction和硬链接文件。

源代码与本机配置需由新桥接进程读取；正常运行 `Start-WeChat.cmd` 后生效。`/reload` 不会安装新后台类或加载新的权限配置。本轮未重启正在运行的机器人，也没有真实微信收发测试。

## 身份门控

已读取并沿用本机 `[bridge] owner_id/owner_name` 的既有人工绑定，姓名为菅蘧；在忽略提交的 `[bridge.computer] owner_id` 再固定同一稳定账号ID。源码与公开模板没有写入个人账号ID。构造时不一致或缺失即拒绝启用。

执行只看当前真实入站原话的 `channel_source.sender_id`，并同时核对允许的平台/群、消息ID、bot非自身回声、live模式、人类作者和明确的 `/pc` 前缀。昵称变化不影响同一账号；同名昵称、正文自称、引用、历史、旁听消息、网页、人格卡均不能授予权限。将来如果换微信账号，需要人工重新绑定；不能让模型自己认领身份。

每轮单独生成 `computer_control` 工具和闭包，不把权限存进共享群handler；其他成员本轮不获得该工具，即使模型伪造调用也不会执行。工具参数为严格空对象：动作和便签内容由宿主从当前 `/pc` 原话解析并绑定，模型不能换账号、改路径、增加命令或扩大动作。

## 执行与证据

主对话模型 → 当前轮空参数 `computer_control` → 宿主身份与动作校验 → 持久task claim → 独立Node进程内的官方 Cordis + Harness ToolRuntime → 固定动作 → 返回真实回执 → 主模型据此回复。

这是使用 Harness 官方工具运行时的小型组合，没有启用二级LLM、通用执行profile、网络插件或任何任意shell；因此本阶段不额外花一轮 Harness 模型费用，也无需把凭据传给执行进程。它不是把安装好的CLI当空壳、再谎称任意脚本就是Harness：`computer-runner.mjs` 真实加载并调用官方 ToolRuntime 注册/执行管线。升级的完整CLI同时可独立使用。

`var/computer-control/actions.sqlite3` 在执行前提交task claim，按渠道消息ID去重并绑定动作指纹。完成结果复用；进程中断、超时或失去回执后保持unknown，不自动重放；同ID换动作拒绝。跨群、并发及服务重启不应绕过此边界。这个SQLite是操作防重记录，不是可以随意删除的缓存。

记事本返回 `launch_submitted` 仅证明系统启动请求成功并有进程ID，不证明用户看到窗口；只有写入/读取回执才能说明便签实际结果。模型意图或一句“已完成”不是执行证据。

## 再安装与诊断

在本项目根目录，用桥版Python运行 `scripts/setup_computer_control.py --node <已有Node绝对路径> --pnpm-js <pnpm.cjs绝对路径>`。安装器复制独立Node、按锁安装、核对版本和无付费探针，然后仅更新本机 `bridge.computer` 表；检测到配置并发修改会停止，不覆盖别人的编辑。凭据不读写。安装证据（版本、Node哈希、owner ID哈希、探针）在不提交的 `var/harness/installation.json`。

如需关闭，设置本机 `[bridge.computer] enabled=false` 并正常重启桥接；只改昵称或角色卡不能改变权限。
