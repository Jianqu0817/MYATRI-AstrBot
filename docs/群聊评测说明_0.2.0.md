# 群聊记忆离线评测（0.2.0）

这套评测用于发现来源检索、成员归属和更正链路的退化。它不调用 LLM，不连接微信，不判断最终回复是否自然、事实结论是否正确，也不能证明超过其他架构。

## 数据及划分

`eval/group_quality_cases.jsonl` 包含 200 个**模板化合成**场景：40 种语义模板，每种有 5 套不同领域事实，覆盖 10 类场景。

| 类别 | 涉及问题 |
| --- | --- |
| identity | 重名、改名、自称冒充、转述者与对象分离 |
| negation | 明确否定、例外、未确认诊断、条件计划 |
| correction | 偏好变化、笔误修正、撤回、转述与本人更正 |
| cross_session | 跨周承诺、聊天边界、共同梗、未完成任务 |
| time | 过去与现在、短期安排、未来计划、固定安排的临时例外 |
| unknown | 没有本人资料、缺少价格、未确认传言、未提供密码 |
| quote | 简短接受、拒绝、两条邀请中的指定回复、省略式更正 |
| paraphrase | 睡不着与睡眠、两轮通勤与交通方式、钱包瘪与预算、躲角落与社交感受 |
| topics | 午饭与游戏交叉、设备故障与闲聊、不同人的承诺、话题返回 |
| attribution | 健康转述、引用他人计划、愿望与已发生事实、虚构职业与本人经历 |

每条原文包含 `message_id / sender_id / sender_name / sent_at / text`，适用时附引用消息 ID。查询有独立的 `current_sender`。评分键包括相关来源 ID、预期证据事实、禁止混入的来源和内容、是否缺少具体答案依据。

开发集 150 例，留出集 50 例；**同一种模板的所有事实变体位于同一 split**，避免仅改人名或事实的近重复跨集。留出模板仍在仓库中公开，开发人员也能看到，不能宣称是未受污染的最终盲测集。未来正式验收需增加未见过的真实去标识场景。

## 两条基线及真实执行路径

1. `unfiltered_lexical`：直接对原文做中文字符二元组 Jaccard 排序，不按成员过滤。它是刻意保留的简单对照，未实现现代向量检索。
2. `member_mixed`：真实调用 `SummaryArchive.save → ArchiveStore → MemoryIndex.update → GroupRecall.recall`，另执行 `claim_projection` 检查更正记录。默认使用本地 TF-IDF 索引；可明确选择已安装的本机 BGE ONNX 模型，不自动下载。

摄取阶段使用夹具内人工编写的 `ingestion_claims`，原样保留否定、转述和假设措辞，并校验精确原文证据。**这不是对 LLM 摘要、事实抽取、支持性复核的测试。** 对话性消息只作为原文保存，不伪造成人物长期事实。

`replay_case()` 不读取 `expected`；专门测试通过会在访问评分键时抛异常的字典验证这一点。查询也是固定场景输入，不从预期答案拼装。每例使用隔离的临时档案与索引，评测结束即清理。

当前每例只有 2–4 条原文，K=5 足以容纳全部原文，成员过滤又进一步缩小了候选库；因此高召回率很容易达到。这可以检验链路与归属规则，却不能代表几万条档案下的检索难度。混合系统获得了人工成员标签，词面基线没有成员过滤；成绩差异不能单独归因于向量、重排或神经模型。修补后可随来源展开显式引用的原话；没有引用 ID 的隐含话题衔接仍需单独评测。这类漏检会如实计分。

## 指标

| 指标 | 含义 |
| --- | --- |
| source_recall | 前 K 个独立原始来源中，召回的预期来源比例；没有预期来源时为 null |
| source_precision | 返回来源中属于标注相关证据的比例；没有返回来源时为 null |
| forbidden_source_exposure | 是否把标注为不应混入的原文放入结果；返回原文并不等于模型采信了它 |
| cross_member_claim_exposure | 是否返回其他主体的个人声明；仅混合系统可观测，词面基线为 null |
| empty_evidence_on_no_source | 完全没有预期来源的案例中，是否没有返回材料；不能等同于正确拒答 |

更正场景同时把旧原文和更正原文列为相关证据，因为检索应保留变化依据；这不意味着旧结论仍有效。专门测试另外验证投影中的旧条目变为 `superseded`，当前条目保留更正来源。仅引用属于他人的证据也不必然是归属错误，评分依据人工标注区分。

不要把来源暴露率写成“幻觉率”，也不要把来源召回率写成“语义回答准确率”。尚未测量：实际模型推理、工具使用、冷存档查询、长期多主题选择、真实群吞吐、延迟、人物风格与自然感。

## 运行方式

在 `D:\DS_workspace\MYATRI-AstrBot` 的 PowerShell 中运行。若桥接虚拟环境尚未安装新核心，可临时设置 `$env:PYTHONPATH='D:/DS_workspace/MYATRI/src'`，测试结束恢复原设置。

```powershell
# 校验全部200例；不构建索引、不调用模型。
.venv/Scripts/python.exe scripts/evaluate_group_memory.py --validate-only

# 每类1例的快速链路回放。
.venv/Scripts/python.exe scripts/evaluate_group_memory.py --sample-per-category 1 --output var/diagnostics/group-quality-quick.json

# 全部200例；每例真实构建本地索引并回放。
.venv/Scripts/python.exe scripts/evaluate_group_memory.py --output var/diagnostics/group-quality-full.json

# 固定留出集，也可以单独运行。
.venv/Scripts/python.exe scripts/evaluate_group_memory.py --split heldout --output var/diagnostics/group-quality-heldout.json

# 可选本地神经向量；整个评测只加载一次，同一实例跨案例复用。
.venv/Scripts/python.exe scripts/evaluate_group_memory.py --embedding bge --model-path var/models/bge-small-zh-v1.5 --output var/diagnostics/group-quality-0.2.0-bge.json

.venv/Scripts/python.exe -m pytest -q tests/test_quality_evaluation.py
```

结果文件记录数据 SHA-256、K、split、类别、每例来源、限制说明及宏平均指标。BGE 模式另记录模型 revision、向量空间、manifest 哈希和经过加载器核对的文件 SHA-256。`llm_api_calls=0` 表示没有远程 LLM 调用；BGE 模式仍执行了本机神经网络推理，`local_embedding_inference=true` 会明确标注。兼容字段 `model_calls` 的范围仅指远程 LLM，不能用于声称没有任何模型计算。相同版本对比时固定这些参数；不要用调参后的开发集数字代替留出集结果。

TF-IDF 仍存在的缺口：`paraphrase/transport` 的 5 例未能从“每天骑两个轮子的那个去……”找到“我平时怎么通勤”的来源。开发集来源精度宏平均98.21%，剩余额外来源来自 `identity/rename` 的“改昵称、饮品没换”上下文；它不属于标注的核心饮品来源，但也不是第三人事实。未修改标注来美化分数。

## 后续模型盲测

```powershell
.venv/Scripts/python.exe scripts/evaluate_group_memory.py --split heldout --validate-only --export-blind var/diagnostics/group-blind
```

导出两个文件：`inputs.jsonl` 只有原文、当前成员、查询和案例 ID；`WITHHELD_scoring_key.jsonl` 保存评分键。**只向待测模型提供 inputs**；不附人工摄取声明或评分键。这个命令本身不会发送任何请求。

将来由用户确认真实测试预算后，固定模型和相同可见输入，随机打乱系统名称，人工独立评定：人物归属、时间与更正理解、未知时是否乱猜、引用是否支持结论、回应是否及时、语言是否自然。必须把检索改善、提示词改善和模型变化分开对照。
