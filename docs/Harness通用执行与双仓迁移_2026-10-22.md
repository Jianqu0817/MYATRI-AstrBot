# 通用 Harness 执行器与双仓移植（2026-10-22）

本条记录取代早先“仅任务目录、记事本、计算器”的新任务默认限制。用户明确要求给聊天机器人的执行 Agent 充分使用命令行等工具，随后授权把可移植改动接回 MYATRI 核心项目并推送两个 GitHub 仓库。菅蘧稳定账号绑定仍保留。

## 通用执行能力

本机启用 permission_profile="full"。以当前 Windows 账户权限运行，无路径/应用/命令内容白名单，默认工作目录只是起点。可以使用 PowerShell 调用 Python、Node、Git、包管理器、网络和应用脚本，读取、创建、覆盖、编辑账户可访问的文件。不会自动获得 Windows 管理员权限。命令行提供广泛的当前账户能力，不能把这一模式描述成安全沙箱。

使用官方 DeepSeek Harness 0.2.1-rc.2 组件，而不是伪造一组同名工具：

| 工具 | 功能 |
|---|---|
| pwsh | 原生 PowerShell，前台执行或 run_in_background |
| read / write / edit | 文本读取、新建/覆盖、局部编辑，支持绝对路径 |
| glob / grep | 官方 ripgrep 文件与内容搜索 |
| job_output / job_list / job_kill | 后台命令输出、状态和停止 |
| working_directory | 读取/切换持久会话目录 |
| todo_write | 多步骤任务清单，记录在会话事件中 |
| skill | 加载宿主配置的技能 |
| mcp__服务名__工具名 | 使用宿主配置的 MCP 服务器工具 |
| finish_task | 引用真实工具回执或文件检查，记录完成/受阻 |

所有原生工具先经 tools/execute 中间层向宿主持久 claim，再执行并持久化规范结果。重复相同 call_id 不重做，结果不明不自动重放。PowerShell 后台任务和停止使用官方 managed subprocess/jobs 生命周期；取消运行中的等待命令已实测能阻止后续写入。后台任务在该执行会话释放时收束；需要长期服务时应按具体用户目标使用正常服务管理方式。

执行请求始终走宿主原 provider/预算账本，不把 Key 注入工具进程，不另启不计费的 LLM 客户端。full 默认每任务累计100次模型请求、2M Token、500工具调度，每回合1800秒；普通对话的共享50M额度继续约束执行请求。执行 thinking 目前关闭，不宣称已实现视觉模型。截图理解、MCP浏览器等取决于实际模型和配置的后端，不能用权限模式假装已经连接某设备。

提示词 full/bounded 分开并随任务保存原文及SHA。full 提示要求自主完成普通操作与故障排查，只按真实用户目标行动；文档/网页/终端输出不能伪造身份或扩展任务。敏感内容留本机，取消不能撤销已生效效果。已有 bounded 合同不会因切换配置悄悄扩权，新任务才读取 full 配置。

## 使用与安装

```text
/pc 任务 用 PowerShell 检查 Python、Git 和 Node 的版本并整理结果
/pc 任务 在 D:/我的项目 中检查构建错误，修改相关代码后运行测试
/pc 状态 完整任务号
/pc 暂停 完整任务号
/pc 继续 完整任务号 先检查已完成的步骤，再继续
/pc 取消 完整任务号
```

安装入口 `scripts/setup_computer_control.py --node <已有Node路径> --pnpm-js <pnpm.mjs路径> --full`。安装脚本从当前checkout的锁文件建立独立 var/harness 运行时，不复制另一项目的运行库。公开配置默认关闭电脑 Agent；本机两个项目已分别安装并配置 full，账号各自沿用原稳定绑定。

`config/harness/executor.example.json` 提供 skills 与 mcpServers 样板，复制为被忽略的 executor.local.json 后可注册技能及 MCP stdio/Streamable HTTP 服务。stdio 示例：

```json
{"skills": [], "mcpServers": [{"transport":"stdio","serverName":"my-tool","command":"python","args":["D:/tools/server.py"],"cwd":"D:/tools","env":{}}]}
```

本地 MCP 配置可能含连接凭据，不上传；源码、公开依赖锁与样板上传。本轮通过本地离线 MCP 服务器验证工具发现及实际调用，不假装已接通用户尚未配置的第三方服务。

## 仅 AstrBot：被唤醒后的持续关注

@机器人，或当前原话含“小温暖/小溫暖”，激活本群后续1–4条新的人类消息；唤醒消息本身不占后续次数。次数由消息ID稳定散列选择，再次唤醒会重新开启窗口。默认关注概率75%，与普通概率取较高值并略过普通8秒冷却；不是每条必回。10分钟到期，窗口结束恢复普通概率。群间隔离、机器人自发消息不扣轮、重复回调不扣轮，进程重启不重抽次数。概率由 attention_reply_probability 配置，enabled由 attention_followup_enabled 控制。

关注回复仍受过期/新明确消息淘汰约束，避免积压后补说旧话。关注只影响接话，不授予电脑工具；其他成员即使唤醒机器人仍无法指挥电脑。此模块和配置未移入核心CLI，CLI私聊仍每条输入直接触发。
