# 本机上下文控制按钮（0.2.7）

在8768实际上下文页面选择微信群会话，新增两个操作：

- **重载角色卡和提示词**：读取桥接配置使用的角色卡文件，正规提交新角色版本，立即作为下一条回复的当前人格；热加载当前运行包的系统提示词模块并刷新旧绑定。保留原始历史、版本来源和群渠道身份规则，不修改角色卡文件。相同内容重复加载不新增无意义人格版本。
- **清空当前上下文**：为选中会话持久保存清窗边界，停止自动回放旧往返、旧会话摘要、旧继承窗口和旧旁听；新消息从新窗口继续。原始记录、长期记忆、人格、情绪和历史捕获保留，长期记忆仍可按需检索。明确引用的旧原话仍能用于理解本轮，不等于恢复整段旧窗口。

原先角色卡只在启动时读取并持久化人格，修改磁盘文件不会自动覆盖运行中的版本；新的重载按钮主动读取文件并更新运行状态，解决这一延迟。按钮不把角色卡文件改写成模型生成内容。

清空会退休旧中断协议和待发候选、清除旧Token校准锚点；旧摘要不会因窗口清空而在下一次压缩中重新吞回旧历史。生成排队、生成中或发送中会提示忙，避免切换发生在半条回复或分段批次中间。按按钮不会调用LLM，也不会主动发微信。

## 使用

1. 首次正常关闭并重启桥接、AstrBot，加载0.2.7。微信可以保持登录。
2. 关闭旧8768查看器进程，再运行View-Context.cmd，刷新页面。仅双击启动入口可能复用旧进程，旧进程没有新的控制路由。
3. 选中目标微信群。修改角色卡后点“重载角色卡和提示词”；需要重新开始近期对话时点“清空当前上下文”。下一条新消息按新状态生成。

下方仍会显示上一次实际请求快照，按钮不会伪造或删除旧捕获；生成新回复后刷新即可检查新角色卡与新窗口。

目前按钮仅支持运行中的微信群会话；命令行私聊没有管理HTTP通道，私聊库按钮禁用并提示重新启动对应窗口。核心已提供clear_context接口，但没有让查看器绕过运行进程直接改私聊档案。

系统提示词重载读取**实际运行包**：桥接以editable源码安装，其系统提示词源码修改可重新加载；核心使用冻结wheel，若修改原MYATRI源码中的提示词，需更新安装包后再加载。内置权限与来源规则继续有效，没有新增任意路径/远程代码输入。

## 本机访问边界

8768通过本机认证代理调用8766管理API，按钮不能直接写生产数据库；请求必须有查看器会话Cookie、同源Origin及专用请求头。令牌只在本机读取，不放到页面或操作响应中。只接受已经观察到的群scope，拒绝任意目录和跨站请求。
