# 只接当前话头（0.2.5）

本轮首要目标：保留丰富上下文，但默认只接当前最相关的话头，减少总结全场和刻意展示记忆。角色卡和README仍由其他窗口维护，本轮未修改。

## 从 QQ-agent 继续借鉴的做法

参考固定提交 [fdfd325 的 src/prompt.js](https://github.com/K0nd1us/QQ-agent/blob/fdfd325e148d91845a0aeea3dfdff4cf92fc61a1/src/prompt.js)。85—112行区分群聊参与与客服队列，125—130行强调相关时自然用记忆，798—805行给出当轮参与指引，844—855行区分历史与新消息，并移除容易诱发“汇报式开场”的冗余状态信息。

适配为本项目自己的规则和输入组织，没有引入上游发送/结束工具或零历史架构，也不要求模型假装真人。旧记录仍可帮助理解关系、指代和语气；进入上下文不等于需要逐条回复。

## 实际修改

- 核心聊天规则新增首要表达目标：当前明确问题、澄清和可靠引用优先；默认一次接一个焦点，说到位就停。
- 对旧事采用必要性判断：若不提旧事仍能准确自然地接话，就不专门提。称呼和已确认偏好可直接融入表达，不先说“我记得你以前说过”。这是表达约束，不删除或覆盖历史。
- 群聊请求在当前user信封前加入独立system“本轮接话重点”。信封内先放recent_messages旁听背景，再放当前成员和原话；字段和来源内容保持完整，背景里的旧问题不自动成为新任务。
- 现有条件式回复审查同步相同目标，版本标记group-reply-guard-v4。仍只在原来的重复措辞/个人记忆断言条件下触发，不新增每轮选题模型或审查调用。
- 明确例外：用户主动要求总结、比较、回忆，或本轮提出多个问题时，按所问范围展开；不机械限制为只能回答一个问题。
- 已核验创作者的轻微依恋可以自然流露，但不额外补一段撒娇、暧昧或共同记忆证明。群成员身份、引用认证、转述及来源边界继续生效。
- 上下文查看器新增“本轮接话重点”分类，便于检查实际请求顺序。

例如背景同时在聊烤肉和显卡，本轮只说“我到家了”，预期接到家这件事；不顺带点评烤肉、回答旧驱动问题、复述对方历史偏好。若明确要求“总结烤肉讨论，不用说显卡”，则按要求总结烤肉。以上是验收目标，不是已经验证的真实模型输出。

## 验证与使用

使用桥接实际安装的核心0.2.5运行64项定向离线检查，全部通过（22.32秒）；涉及当前消息顺序、完整背景和原始记录保留、明确总结/回忆例外的规则送达、群成员身份与引用、审查、查看器、质量测试及聊天排版。Ruff通过。Fixture证明机制和规则送达，不证明真实模型已经解决相关性。

两项目已安装到0.2.5；桥接vendor wheel、uv.lock、UPSTREAM_LOCK.json哈希以及实际安装的reply.py核对一致。未修改上下文容量、召回排序、记忆数据、回复概率或后台维护频率；未调用付费模型、发送微信、重启现有服务或上传GitHub。

正常关闭机器人启动窗口，从原入口重新启动即可加载。需要检查新分类时，也重新打开View-Context.cmd；微信可保持登录。在新请求中核对当前text、可靠引用、旁听背景与“本轮接话重点”，再结合真实回复判断效果。
