## 两项修复

### 搜索目录与读取原文分开

`recall` 内部仍使用原有 `GroupRecall`、完整 `RecallBundle`、人物过滤和快照规则。仅在送给模型前投影为最多5个结果：精确 `ID@revision`、时间、记录类型、短摘录、是否完整摘录和 `read_record` 入口；目录本身明确标记 `original_read=false`，不能冒充全文。

对内部预算未能容纳的长候选，只采纳检索器明确给出的预算省略指针和早期原文定位；不会从过滤前的reasons或图路径重新捞回其他成员。每个指针必须能在本次检索快照中解析。目录提供 `has_more/omitted_count`；不是整库枚举接口，未显示的搜索结果需缩小查询继续定位。

模型可用 `read_record(ref, offset=0, limit=800, field=...)` 读取字段：

- `body_markdown`：正文；有正文时默认读取此字段。
- `payload_json`：结构化数据；无正文时默认读取此字段。
- `source_refs_json`：完整来源引用。
- `metadata_json`：其余完整记录元数据。

每次返回的是指定字段的文本片段，JSON字段可能需要拼接全部页后才构成完整JSON。正文页另带原记录的发言者、谈论对象和自述/转述等简短归属投影，避免把说话人和谈论对象混用；完整结构仍在 `payload_json`。偏移量以Python字符计数；上限按实际 `json.dumps(..., ensure_ascii=False).encode('utf-8')` 的字节数计算，包含JSON转义和进度字段。先省略说明、附带来源列表等元数据，再缩短实际页面；不会把已经移除的字符计入成功读取区间。极大归属投影也可省略，但不会截断账号ID制造新身份，且非空正文页保持向前推进。完整来源列表和元数据仍可按字段分页获取。`read_group_message` 冷档工具沿用现有入参，也应用相同字节和缺页检查。

搜索和原文页均控制在6000 UTF-8字节以内，来源入口不会因大段诊断被整包替换成错误。无效版本、超出快照、越界offset或非法参数仍返回明确工具错误，失败不计作已读。

### 用实际返回区间判断是否读齐

`read_progress` 按本轮的精确版本和字段分别合并成功返回的区间，包括同一轮多个工具调用及未完成协议恢复后的结果：

```json
{
  "field": "body_markdown",
  "covered_ranges": [[0, 800], [3200, 4070]],
  "complete": false,
  "first_unread_offset": 800
}
```

`next_offset=null` 只表示当前页到结尾；上述例子仍漏读800—3200。`complete` 仅说明当前版本的当前字段已经返回齐，不认证整库、所有字段或模型的理解质量。区间很多时仅展示前12段和省略数量，完整判定仍使用全部成功区间。已有足够片段证据可以直接回答，不要求为每个事实读完全文。

工具定义和本轮系统规则要求按 `first_unread_offset` 补缺页。已有回复审查之后、最终字数整理之前再做本地检查：若仍有缺页或只有搜索目录却声称“读完/全文没有任何”等，替换为诚实的部分读取说明。读取失败时声称查到原话也有保守回退。这是针对明确措辞的本地检查，不是语义模型，不能保证拦截所有同义虚构；正常引用已读片段和本轮已提供原话不要求新增工具或LLM调用。
