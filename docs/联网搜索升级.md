# 联网搜索升级：把 web_search 从 DSH 子进程切到 DeepSeek Search API

> 交接文档。目标读者：在本仓库继续实现的 Agent。
> 编写时间：2026-10-22。基线：桥接 0.2.8，`[bridge.web] enabled = true` 已在本机生效。
> 本文里的接口事实全部来自官方文档与 2026-10-22 本机实测，不是推测；引用处标了来源。

## 0. 一句话

现在每次 `web_search` 都要起一个 `dsh --profile headless` 子进程、跑多轮模型请求，再由子代理输出 JSON；而 DeepSeek 在 2026-10 中旬开放了独立的 Search / Fetch HTTP API（每 1000 次成功请求 5 元，失败不计费）。把后端换成直连该 API，可以让单次搜索从 5–25 秒降到 **0.9 秒**左右，并且不再消耗搜索子代理的模型 token。

**硬截止：2026-11-01 00:00（北京时间）起**，DeepSeek Harness / Claude Code / Codex 里通过服务端工具调用访问 Search/Fetch 也开始按次计费（官方文档原话）。也就是说"现在免费"这条理由 9 天后失效，切换越早越好。

## 1. 现状（不要凭想象改，先读这三处）

### 1.1 代码地图

| 文件 | 现有职责 |
|---|---|
| `src/myatri_bridge/web_tools.py` | `WEB_SEARCH_TOOL`（function schema）、`WebSearch`（SQLite 缓存 + 日限额 + 审计 + 6000 字节截断）、`DshBackend`（把 query 交给子进程）、`parse_output`（严格校验子代理输出的 JSON） |

| `src/myatri_bridge/bridge.py` | `Bridge.__init__` 读 `[bridge.web]`：`enabled` 时强制要求 `node_path`/`bin_path`（约 157–163 行）；`_application()` 注册 `tool_handlers["web_search"]`，用 `asyncio.to_thread` 调 `WebSearch.search`（约 273–282 行）；`_web_tool()` 建 `DshClient` + `WebSearch`，每群一个 `web.sqlite3`（约 295–332 行） |
| `config/bridge.local.toml` | `[bridge.web] enabled = true`、`timeout_seconds = 25`、`max_results = 3`、`daily_limit = 40`、`cache_ttl_hours = 24` |
| `config/bridge.example.toml` | 同上模板（注释说明"默认关闭"） |

### 1.2 现有调用链

```
模型 (deepseek-flash) → function call "web_search"
  → Bridge._application 注册的 async wrapper（asyncio.to_thread）
    → WebSearch.search()：查缓存 → 扣日限额 → backend(query)
      → DshBackend → DshClient.run() → node … --profile headless <prompt>
        → 子代理再调一次 DeepSeek Messages 搜索（辅助模型请求）
        → 子代理把结果拼成 {"results":[…]} 文本
      → parse_output() 严格校验 → 写缓存 → 审计
```

### 1.3 本机实测状态（2026-10-22，作为基线）

- 某群 `var/groups/<scope>/web.sqlite3`：10-21 用了 6 次、10-22 用了 7 次，缓存里 10 条结果 → **链路是通的，不是坏的**。
- 一次搜索在会话记录里表现为：`web/deepseek-search-llm-request` + 标题请求，属于**辅助模型请求**，所以慢、且按 token 计费。
- 现有错误码只有四个：`search_timeout` / `search_backend_failed` / `search_output_invalid` / `search_quota_exhausted`（`web_tools.ERROR_CODES`）。**本次不要扩充错误码集合**，前端/审计和测试都按这四码写死了。

## 2. 目标设计

### 2.1 架构

只替换最内层后端，外面全部保留：

```
模型 → web_search (schema 不变)
  → Bridge wrapper (asyncio.to_thread，保持不变)
    → WebSearch.search()：缓存 / 日限额 / 审计 / 6000 字节截断（全部保持不变）
      → DeepSeekSearchBackend（新增）：httpx POST /v1/tools/search
```

- 新增模块 `src/myatri_bridge/deepseek_search.py`，实现与 `DshBackend` 同形的可调用对象。
- `[bridge.web] backend` 新增开关：`"deepseek-api"`（新的默认）| `"dsh"`（保留，可一键回退）。
- `DshClient` / `DshBackend` 一行不删；`backend="dsh"` 的既有测试必须继续通过。

### 2.2 接口契约（官方文档原文 + 本机实测）

Base URL：`https://api.deepseek.com`，操作路径 `/v1/tools/search`、`/v1/tools/fetch`。
鉴权：`Authorization: Bearer <DeepSeek API Key>`，`Content-Type: application/json`。

**Search 请求**

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `query` | string | 是 | — | **1–128 个 Unicode 字符**，不能全空白 |
| `count` | integer | 否 | 10 | 1–50 |
| `ori_question` | string | 否 | — | 触发搜索的用户原话，1–128 字符 |
| `localization` | string | 否 | "" | 用于本地化的 IP |
| `need_content` | boolean | 否 | false | 为 false 时 `content` 恒为空串 |

未知字段会被忽略。

**Search 响应（HTTP 200）**

```json
{"results":[{"rerank_score":2.4,"title":"…","url":"https://…","snippet":"100–200 字",
  "summary":"600–800 字","content":"","site_name":"…","site_icon":"…",
  "date":"2026-06-01T00:00:00+00:00","authority":3}]}
```

- `results` 为空数组 = **成功**，不是失败。
- `rerank_score` 0–3，≥1.5 为优质；`authority` 0–4，≥3 为极权威。
- `date` 是 UTC RFC3339 或 null。

**Search 语法**（直接写在 `query` 里，原样透传）：`site:` / `-site:` / `-词` / `-"短语"` / `"精确短语"` / `lang:zh,en` / `after:2025-01-01` / `before:2026-06-01`。

**Fetch 请求/响应**：`{"url": "…"}` → `{"title": "…", "content": "Markdown"}`。

**错误码**

| HTTP | 含义 | 处理建议 |
|---|---|---|
| 400 | 请求头/体不合法（含 query 超 128、count 越界） | `search_backend_failed`，不重试 |
| 401 / 402 / 403 | Key 无效 / 余额不足 / Fetch 被安全策略拒 | `search_backend_failed`，日志里区分一句 |
| 404 | Fetch 拿不到可提取正文 | 仅 Fetch 路径 |
| 408 / 413 / 429 / 5xx | 超时 / 体过大 / QPS 超限 / 服务端错 | `search_backend_failed`，**不做自动重试** |
| 传输超时 | httpx `TimeoutException` | `search_timeout` |

**计费**：Search、Fetch 各 5 元 / 1000 次**成功**请求；只有 HTTP 200 且 Search `results` 非空、Fetch 返回正文才计费；失败、无结果、超时不计费。`count` 不影响单价。
**限速**：账号级 Search 100 QPS、Fetch 25 QPS（与 Key 无关）；Fetch 还对目标域名单独限速。

本机实测（2026-10-22，真实计费一次）：`count=3` 请求耗时 **0.88s**，返回 3 条，字段齐全（`title/url/snippet/date`），Fetch 接口抓官方文档页返回 200 + 可解析 Markdown。

### 2.3 字段映射（关键决策）

| API | 落到 `results[]` | 理由 |
|---|---|---|
| `title` | `title` | 直接 |
| `url` | `url` | 必须是 http(s)，否则丢弃该条（沿用 `parse_output` 的规则） |
| `summary` | `snippet` | 600–800 字，比 `snippet`（100–200 字）更适合喂模型；`summary` 为空时退回 `snippet`；最终按现有 `MAX_SNIPPET_CHARS=1200` 截断 |
| `date` | 暂不落 | 现有 `parse_output` 只认三字段；要加 `published_at` 需同时改工具结果渲染与测试，建议放到 P2，别在本轮顺手加 |
| `content` | 不使用 | `need_content: false`，省流量 |

**query 长度坑**：现有工具 schema 允许 200 字（`MAX_QUERY_CHARS`），API 只收 **128**。后端必须在拼完 `after:` 之后再做截断（或者把 `MAX_QUERY_CHARS` 下调到 128 并同步改 schema/测试）。**两种只能选一种，不能不管。**

**`recency_days` 落地**：拼 `after:YYYY-MM-DD`（`today - recency_days`，Asia/Shanghai 计算，再转日期）。拼接顺序：先 `query` 原文，再追加操作符，最后统一截断到 128。

## 3. 变更清单（按顺序做）

### 3.1 新文件 `src/myatri_bridge/deepseek_search.py`

- `class DeepSeekSearchBackend`：`__call__(self, query, *, max_results, recency_days, timeout_seconds) -> str | list[dict]`。
- 建议沿用现有协议：**返回 `json.dumps({"results":[…]}, ensure_ascii=False)`**，这样 `WebSearch.search` 与 `parse_output` 完全不用改（改动最小、测试最少）。若你想返回 `list[dict]`，则必须同时重构 `SearchBackend` 协议、`DshBackend`、`parse_output` 三处，不推荐本轮做。
- 内部：`httpx.Client(timeout=timeout_seconds, follow_redirects=False)`；成功解析后只映射三字段；任何非 200 / 解析失败抛 `WebSearchError(...)`（从 `web_tools` import，避免循环依赖：把 `WebSearchError`、错误码常量留在 `web_tools` 即可，`deepseek_search` 单向依赖它）。
- 不打印 query 原文、不打印 Key、不打印完整响应体；失败只记 HTTP 状态与端点数。
- 构造参数：`base_url`（默认 `https://api.deepseek.com/v1/tools`）、`count_ceiling`（默认 50）、`use_summary`（默认 True）。

### 3.2 `bridge.py`

1. `__init__`：`[bridge.web]` 的必填校验按 `backend` 分支——`dsh` 才要求 `node_path`/`bin_path`；`deepseek-api` 只要求有凭据（`read_deepseek_key()` 为空时**不**构造后端，与现在"少 Key 只少 key 不报错"的行为保持一致，但要打 `warning`）。
2. `_web_tool()`：按 `backend` 选后端；`DeepSeekSearchBackend` 不需要子进程、不需要 `default_workdir`。
3. 凭据读取仍走 `from myatri.credentials import read_deepseek_key`（Windows 凭据管理器），**不要**把 Key 写进 `bridge.local.toml`、日志、审计。
4. 未知 `backend` 值：启动即 `ValueError`，别静默回退到 dsh（静默回退会让人以为切换成功但仍在花钱跑模型）。

### 3.3 配置

`config/bridge.local.toml` 与 `config/bridge.example.toml` 的 `[bridge.web]` 调整为：

```toml
[bridge.web]
enabled = true
backend = "deepseek-api"          # "deepseek-api"（默认）| "dsh"（回退）
base_url = "https://api.deepseek.com/v1/tools"
timeout_seconds = 8               # 直连 API 不需要 25s
max_results = 5                   # 条数不影响单价，3→5 是免费的质量提升

cache_ttl_hours = 24
# 仅 backend = "dsh" 时需要：
# node_path = "…/node.exe"
# bin_path  = "…/@deepseek-ai/dsh/lib/bin.js"
```

注意示例配置的注释里"默认关闭"的措辞要同步改（`enabled` 在本机已经是 true，别再写"默认 false"误导下一个人）。

### 3.4 不要改的东西（明确边界）

- `config/engine.toml`（模型端点仍是 OpenAI 兼容的 `https://api.deepseek.com`，与本次无关）。
- `~/.dsh/profiles/headless/*`（不要靠改 DSH profile 的 `searchProvider` 来"实现"本需求，理由见 §6）。
- 共享 50M 日预算机制（用户此前明确保留：搜索不继承该额度）。搜索侧的账本仍然是 `web.sqlite3` 的日次数。
- `dsh_client.py` 的任何行为（超时、白名单、read-only）。它以后只作为回退路径。

## 6. 为什么不走"只改 DSH profile"

把 `~/.dsh/profiles/headless/cordis.patch.yml` 里的 `@deepseek-ai/dsh-web` 配成 `searchProvider: deepseek-search-api` 确实 5 行就能用上新 API，但：

- 仍然要起子进程、跑子代理模型，延迟与 token 一分不省；
- 11/1 之后搜索本身也按次计费，等于模型 + 搜索双份成本；
- 子代理还需要把结果重排成 JSON，`parse_output` 的脆弱性依旧。

它只适合当"应急开关"，不能当本次交付。

### 6.1 为什么不让模型走"原生服务端搜索"

- `config/engine.toml` 的端点是 `https://api.deepseek.com`，即 OpenAI 兼容的 `/v1/chat/completions`。官方 API 文档（2026-10-22 抓取）在该端点的 `tools` 参数下写明：**"目前，仅支持 function 作为工具"**——这个端点不会替模型执行网页搜索，工具调用必须由宿主执行。
- DeepSeek 的原生 `web_search` 工具只在 **Anthropic 兼容端点** `https://api.deepseek.com/anthropic/v1/messages` 上提供（DSH 的 Messages 搜索就是这么实现的，其 provider 文档写明 base 为 `https://api.deepseek.com/anthropic/v1`、追加 `/messages`）。要用它得把整个网关切到 Anthropic 协议，而且每次搜索仍是一次完整模型请求（慢、按 token 计费），并不会比现在的子进程便宜。

结论：**模型不会自己发 HTTP**，能"直接调用"的只有宿主代码。所以本次走 §3 的宿主直连方案。

## 7. 风险

| 风险 | 说明 |
|---|---|
| 计费口径 | ¥0.005/次成功请求；日限 40 次 ≈ 0.2 元/天。失败不计费，但**429 也可能计入失败**，所以不要靠重试刷 |
| 空结果 | 官方"空数组 = 成功"；现在的 `parse_output` 对空数组返回 `[]` 也是成功，语义一致，但**日限额是在调用前扣的**，空结果会白扣一次。建议（P2，可选）：改成"拿到 200 才扣"，同时改 `test_web_tools.py` 的配额用例 |
| query 128 字上限 | 现有 schema 是 200，必须处理（§2.3） |
| 凭据 | 缺 Key 时不要构造后端、不要静默降级到 dsh；日志只说"缺凭据" |
| 本机网络 | 不影响：Python/httpx 走系统 DNS + Clash TUN 正常（实测 200）。见附录 A |

## 附录 A：本机网络为什么 web_fetch 会被拦（与本改动的区别）

- 本机 Clash Verge 开着 TUN + mihomo `fake-ip`（`198.18.0.0/16`），`api-docs.deepseek.com` 会解析成 `198.18.0.60`。
- DSH 的 `web_fetch` 在抓取前做 SSRF 校验（`isPublicIpAddress`），命中保留段即抛 `WEB_BLOCKED_URL: resolves to a non-public IP address`。
- **这是 DSH 自带工具的限制，不是 DeepSeek 的限制，也不影响本项目的 Python 代码**：`httpx`/`curl` 走同一套 DNS 能正常拿到 200。
- 因此本次改动不需要动代理、不需要管理员权限。若将来要恢复 DSH 自带 `web_fetch`：在 Clash Verge 里把目标域名加入 `fake-ip-filter`（或整个 DNS 改 `redir-host`），需重启内核。
- 附带发现：`C:\Windows\System32\drivers\etc\hosts` 目前是 2331 字节全 `0x00`（2026-10-15 19:20 写入），文件已损坏，建议用管理员权限重写为标准内容——**与本需求无关，不要顺手改**。
