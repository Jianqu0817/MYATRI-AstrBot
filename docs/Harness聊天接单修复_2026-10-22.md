# Harness 聊天接单修复（2026-10-22）

用户反馈电脑任务被回复“我进不了你的电脑”。本轮只修复 AstrBot 桥接入口，不改核心私聊库或角色卡。

## 诊断

只读核对最近三个实际请求与回复：软件版本检查、磁盘容量、内存容量。电脑任务库为空，这些请求没有进入执行器。发现两个独立原因：

1. 本机 bridge.owner_id 与 computer.owner_id 虽然一致，但都少了微信原始 sender_id 的最后一个字符。双字段一致不能证明配置与实际账号一致。
2. 原解析器仅认消息开头的 /pc，不识别微信 `@小溫暖<空白>/pc ...`。带 @ 的命令因此没有本轮电脑工具。

身份纠错依据用户本轮明确指认的失败操作及其原始渠道信封，修正本机两处精确绑定并备份旧配置。没有基于昵称自动认主，没有加入近似账号匹配或多个 owner，也没有改历史消息。备份与诊断证据在被忽略的 var/setup-backups 与 var/verification；本机账号不写入公开文档。

## 修复

command_body 统一接单与执行任务解析：支持直接 /pc、前置 @小温暖/@小溫暖 和微信空白字符，旧固定命令兼容尾随 @。只识别当前原话的开头，不从叙述、引用或历史提取命令。便签正文、任务目标中的 @ 文本原样保留。账号 ID 仍逐字匹配，群及当前人类来源检查不变。

授权的明确 /pc 命令由宿主直接调用原有零参数处理器，原始用户消息、助手回执、已完成协议与回调仍正常落盘。接单不再依赖主聊天 LLM 选择工具，也不为接单额外调用模型；独立 Harness 执行 Agent 仍通过原 provider 与共享账本规划执行。

回执由真实状态生成，包含完整64位任务号。queued/running 不会渲染为完成。群聊只回任务状态及本机面板提示，文件正文、路径及执行器输出不会因接单写入群回执或助手回执元数据。既有任务 claim、重复入站去重、unknown 不自动重放不变。

## 用法

下面两种写法均可：

```text
/pc 任务 查询当前内存容量
@小溫暖 /pc 任务 查询当前内存容量
```

应立即得到任务号和排队状态；实际结果在 http://127.0.0.1:8767/ 的电脑执行 Agent 面板查看。任务状态可用 `/pc 状态 完整任务号` 查询。旧失败消息保留原记录，不自动重新执行。
