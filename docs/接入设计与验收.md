# AstrBot 接入设计与验收

2026年10月21日。当前交付是可运行、已做本地模拟联调的群聊桥接；尚未登录真实微信，也未验证任何个人微信群协议在用户账号上的可用性。

## 本次改动

原 MYATRI 的引擎代码和私聊运行库不需要为本次桥接改写。新项目固定使用已发布的0.1.7 wheel；原项目只新增修改记录和接入指引。AstrBot源码独立克隆，保持上游代码不改；插件复制到其运行数据目录。

消息链路：平台适配器将真实群消息转为 AstrBot 事件；插件检查群白名单、稳定ID、@或显式前缀，然后调用本机后端。后端按群隔离上下文，交给既有 Conversation、ArchiveStore 和认知维护；生成正文经领取与发送回执流程返回原群。AstrBot不再额外请求第二个LLM来改写回复。

## 已实现的边界

只接收群聊文字。未提及机器人、自己发的消息、范围外群、缺失必要身份字段均不触发模型。接收过的同一消息ID重复到达不会重新生成；相同ID但内容变更会报冲突。平台实例、机器人和群共同参与隔离键。

入站消息保存群ID、成员ID、可变昵称、原平台发送时间和原文。存档创建时间另为本地接收时间。引擎看到的是结构化信封；不通过字符串冒充系统消息。角色中补充群聊来源解释，其他成员不是默认的创造者或恋人。

目前同群共享记忆，不存在群内成员的私人子会话；群里说出的内容可被同群后续上下文使用。不同群与原私聊库完全分开。发送者字段的真实性依赖平台适配器，桥接仅能验证非空及格式，不能从昵称推导或认证身份。机器人、群和成员ID能否稳定获取，是选择微信适配器的实机验收项。

所有群的前台及后台模型用量共享桥接预算账本，默认每日50M。复用50轮维护和650k压缩前的依赖处理；已加载群有后台维护，重启后在该群下一次接入消息时恢复其后台，不宣称离线期间持续运行。

投递状态与记忆生成分开保存。回复原子领取，避免两个回调同时发送；发送结果不明时保守保留unknown，不能自动重发并声称exactly-once。插件直接调用当前事件的send方法，不经过默认LLM二次生成。接口报错时停止当前事件，日志只记异常类型，不向群发送调试详情。

## 离线验证

测试覆盖白名单和@门控、原文与发送时间保留、成员标识、同群上下文、跨群隔离、共享预算账本、重复请求、内容冲突、冷却、并发领取、发送中断恢复、HTTP鉴权和输入检查。另有使用实际AstrBot 4.29.1的事件对象、组件、注册装饰器和插件类，对真实桥接HTTP服务做模拟群消息联调；发送由本地捕获器替代，没有外部消息。

后续新增群人格修改后的重启检查，确保不会在重启时用初始模板覆盖群里已保存的人格版本。最终测试数量和耗时见 `validation.xml` 与 `verification.json`。验证不包含微信登录、真实收发、长周期群聊语义和650k真实压缩。

## 后续配置

已只读检测到本机Weixin版本4.1.15.13。仍需选择兼容适配器，并取得实际AstrBot平台实例ID与测试群ID；确认该适配器提供真实稳定的成员ID、消息ID和@组件。默认使用非重要账号和一个测试群，先offline收发，再切换live；不先导入全量私人记忆。

当前插件默认为关闭，后端空白名单。修改两个地方的白名单并启用插件是渠道配置，切live是模型调用配置；二者独立。原项目的E01主动社交仍未实现，群聊被@应答不等于已经实现主动搭话、定时发送或跨平台社交意图闭环。
