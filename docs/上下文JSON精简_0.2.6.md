# 上下文 JSON 精简（0.2.6）

目标是减少不必要的结构和内部诊断信息，使模型更容易看到实际聊天。精简只发生在发给模型的投影层，不改归档原文、角色卡或记忆数据，也不缩短已经配置的对话窗口。

## 精简范围

1. 群聊当前消息、已确认的历史往返和旁听消息统一使用精简信封。省去每条重复的platform_id/group_id/bot_id、内部topic_id、默认text类型，以及空的引用/提及字段。消息ID、成员ID、昵称、发送时间、正文、非空提及、引用原文与验证状态继续提供。机器人消息显式标记role=assistant；同名成员仍由ID区分。
2. 成员资料只提供一份名单和手工owner绑定。省去重复current_member、每人重复的scope、last_seen、可由owner推得的布尔字段和与显示名相同的别名。旧姓名/ID候选仍保留未确认状态和证据来源，不升级身份权限。
3. 个人主张的active/history不再重复整段文本：history保留原条目，active_refs引用其中当前候选。历史里未包含的活跃条目会补入，避免因去重漏掉旧约定。更正、撤回、冲突链接和未知时间保留。
4. 群摘要去掉本地attention_score，以及与外层相同的逐项window_end/created_at。说话人、谈论对象、转述/自述区别、原文引用、来源ID、更正关系和不确定性保留。active_topic与summary_attention等排序诊断留在本地explain_context中，不送入聊天正文。
5. 核心召回不再给每条记忆附上检索渠道列表；完整理由仍在本地recall_reasons。反证、原始来源关系、临时状态/历史版本与最早保留记录的限定继续作为evidence_notes发送，不能把它们当无关字段删去。摘录范围和是否完整仍可核对。
6. 核心状态/回忆/摘要/继承历史，以及两种对话入口的工具外层JSON改用紧凑分隔符；不修改聊天正文中的空格、换行或JSON文字。工具分页、来源、哈希、读取区间、first_unread_offset及complete保持原语义。payload_json/source_refs_json/metadata_json的被分页文本维持原序列化，避免恢复读取时改变字符偏移。

没有新增每轮模型调用或选题组件，回复概率与维护频率不变。保留必要JSON边界，以免同名身份、引用来源和资料中的伪系统指令失去区分；没有把所有结构盲目改成散文。

## 本地验证

合成100条短群消息，仅比较“近期消息+当前消息”信封：旧46002字节，新22671字节，UTF-8体积减少50.7%；原有100条消息的正文、ID、昵称、时间逐项一致。此数值不是完整请求的下降比例，也不是API实测Token数；长消息场景比例会不同。测量存在桥接var/context-json-0.2.6.json，无真实聊天内容。

首次181项定向离线检查通过（73.66秒）；补充3项证据角色用例后，对受影响部分复验29项通过（19.17秒）。两轮合计184个不同检查，覆盖真实请求投影、同名隔离、手工绑定、引用匹配/未匹配、资料注入边界、原始记录不变、原文空格与换行、主张更正、反证/历史版本、旁听和历史连续性、工具分页及读取覆盖、摘要和上下文捕获。Ruff通过。未执行真实付费模型测试，因此节省结构开销不等于已证明注意力或自然度提升。

两项目及桥接冻结依赖均为0.2.6；vendor wheel、UPSTREAM_LOCK.json、uv.lock与安装后的context.py/serialization.py已核对一致。包不包含本机配置、数据库或请求捕获。

## 生效方式

正常关闭机器人启动窗口，再从原入口启动，随后在8768查看新一轮实际请求；界面仍完整呈现真正发给模型的内容。已有旧捕获不会被改写。微信可保持登录。本轮未自动重启服务、发微信、调用付费模型或上传GitHub，也未改其他窗口维护的README和角色卡。
