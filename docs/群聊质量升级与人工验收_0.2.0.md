## 实际行为变化

1. **基础索引与增量。** 新消息入库不再自动使所有基础向量失效。仅使用同一档案链的较早索引，过滤已改版记录与非本轮人物候选；新记录用原空间计算增量。较新索引不能污染历史快照，旧主题及图不越过快照边界。向量先按候选过滤再取Top-K，避免其他人的结果挤占个人回忆名额。
2. **收信与生成分开。** 入站消息先持久保存，模型等待期间继续旁听；按群串行生成，不同群可以并行；同一消息并发回调合并。等待请求被取消时已持久化的生成继续完成，进程退出则保留原始输入供原消息ID重试，不声称有自动发送恢复。
3. **随机回复时效。** 45秒TTL或后来的明确呼叫可淘汰旧随机回复；生成后与领取发送前再次检查。明确呼叫仍按队列回应；发送结果未知仍不自动重发。TTL与关键词概率分别配置。
4. **话题衔接。** 保留附近完整问答，同时从较早的已确认问答补入相关话题，最多15轮。最多20条近期消息另作背景，按ID去重。话题依据明确引用、词面及短回应邻接推测，仅作注意力线索，不是已认证事实或现实关系。
5. **引用传输。** AstrBot真实Reply/At组件可传递引用ID和@账号。当前WeChatAgent读取端提供完整的文字quoteReply时，可传递引用资料；截断、跨群或附件正文不冒充完整原文。服务器svrid与本项目rawid不同，不能直接混用；只有同群近期真实原话按账号和全文唯一匹配时，才绑定真实消息ID。未匹配引用不认证被引用人或成为其亲口证据。
6. **记忆语义审查。** 100条旁听摘要含个人声明时，额外整批审查一次否定、时间、主体、转述和结论力度；不支持或不确定的条目留审查记录，不注入为长期事实。原有A1群聊提炼路径也增加支持审查。已验证提取草稿持久保存，审查临时失败后复用草稿。模型审查仍会出错，不等于外部事实核实。
7. **更正与关系。** 个人偏好、称呼、约定、相处边界可用动态facet保存；只用同一主体、同一facet、明确旧消息ID的更正/撤回替代旧理解。不自动覆盖无链接的矛盾，保留未解决的候选。不同成员的亲密、误会、偏好分别归属；临时心情不自动改人格，不做对群友的心理诊断。
8. **上下文选择。** 最近10份摘要按当前人物、话题、更正和约定选择，控制投影长度并公开省略数量。个人回忆先筛候选再分配预算，结论带原话、解释和显式引用一起选择。默认群聊回忆材料额度8000字符；并非每轮把整库塞进提示词。
9. **针对性回复检查。** live模式对具体个人记忆断言、内部账号ID或高度重复的措辞额外审查一次；普通回复不增加这一调用。审查失败时不把可疑记忆当作确证发送。最终仍走40—80字表达规则，记录检查状态；实际文风需用户盲评，不能凭单测保证。

## 冷存档与开销

用户已选本机30天：`config/bridge.local.toml` 的 `cold_retention_days=30`，通用示例默认0。原文使用SQLite中的zlib压缩，仅保存本机；最近200条仍是活跃库。过期内容立即不能读取，后台每小时及新消息到来时清理过期冷档。关闭冷档配置并重新启动会清除该库，不会清除独立的长期档案或摘要。

模型可用只读 `read_group_message` 按消息ID分段核对本群原话；别群、过期或未保留内容返回不可用。此工具不下载附件、不发送消息。确认成功的助手回复可作摘要上下文，但不计入100条人类消息、不能用作人类新证据。

已有可恢复消息通过 `scripts/backfill_group_memory.py` 迁入冷档及话题投影；不改原档案。重复执行不重复计数。后台仍按20/200/100/10、30/50、650k与每日全群共享50M预算运行。旁听摘要出现个人声明时约增加一次支持审查；A1、复杂回复按需要检查，不承诺零额外开销或更低总延迟。

## 用户验收

关闭旧机器人启动窗口后，重新运行 `Start-WeChat-Live.cmd`；微信可保持登录。验收过程中可正常发消息，本次未替你向群里发任何测试内容。

- 两个人分别说不同偏好，再各问一次，确认不串人；昵称改动后仍能衔接。
- 先说偏好，过一段时间明确更正；分别问“现在”和“以前”，核对时间与来源。
- 两个话题交叉聊，引用较早邀请只回复“好啊”，确认接的是对应邀请。没有对应原话时应少作断言。
- 模型生成较慢时继续发普通群消息，之后检查旁听仍在增长；迟到的随机插话不应打断新的明确呼叫。
- 正常聊一阵，评估重复套话、反问、语气及亲密程度。程序检查不能替代这一步。
